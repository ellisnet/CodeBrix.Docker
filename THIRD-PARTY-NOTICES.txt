CodeBrix.Docker is a fully managed, zero-dependency .NET library for managing,
diagnosing, and optimizing Docker containers and images via the Docker Engine
API, targeting .NET 10.

Like some CodeBrix libraries, CodeBrix.Docker incorporates a limited amount of
third-party source code: portions of its Docker Engine API transport,
stream-multiplexing, and wire-model code are adapted from the Docker.DotNet
library. Docker.DotNet is distributed under the MIT License, which is
compatible with this project's MIT License. Its copyright notice and license
text are reproduced below, as the MIT License requires.

Scope of incorporation:
  Unlike CodeBrix libraries that port an upstream project wholesale, only
  selected portions of Docker.DotNet were adapted into this repository under
  src/CodeBrix.Docker/. The adapted areas are:
    - The Docker stdcopy stream-demultiplexing protocol handling
      (upstream MultiplexedStream.cs), adapted as
      Containers/MultiplexedStreamReader.cs.
    - Docker Engine API wire-format model shapes (field names, types, and
      endpoint/query-string conventions from the upstream Models/ and
      Endpoints/ directories), consulted as reference for this library's
      System.Text.Json data-transfer types.
  Individual source files that substantially incorporate upstream code carry a
  header comment identifying their Docker.DotNet origin.

Modifications made during the adaptation (per CodeBrix family conventions):
  - Rewritten for .NET 10 idioms: the upstream Microsoft.Net.Http.Client
    custom HTTP stack was replaced with SocketsHttpHandler.ConnectCallback
    over NamedPipeClientStream (Windows) / UnixDomainSocketEndPoint
    (Linux/macOS); no upstream transport code was retained.
  - JSON serialization was rewritten from Newtonsoft.Json to the in-box
    System.Text.Json; the library has zero NuGet dependencies.
  - All types were renamed into the flat CodeBrix.Docker namespace with an
    async-only public API surface.
  - Strong-name signing was not adopted.
